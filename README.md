# Watchroom

Совместный просмотр прямых ссылок на видео: комнаты по приглашению, общий play/pause и перемотка, чат в реальном времени.

## Архитектура backend

Функциональность комнаты находится в `backend/internal/features/rooms` и разделена на три слоя:

- `repository/memory` — хранение комнат, атомарные изменения, изоляция возвращаемых копий и подписки на изменения. Это in-memory реализация, а не подключение к PostgreSQL.
- `service` — сценарии создания и входа, проверка доступа, валидация видео/воспроизведения/сообщений и ограничение истории чата. Интерфейс `Repository` объявлен здесь, на стороне потребителя.
- `transport/http` — маршруты фичи, JSON, HTTP-статусы и SSE. Интерфейс `Rooms` объявлен в транспорте; конкретный сервис и репозиторий ему неизвестны.

Общие типы состояния находятся в `model`. Зависимости собираются вручную в `backend/cmd/server/main.go`: memory-repository → service → HTTP-handler. В памяти сервиса нет хранилища комнат и блокировок. `Repository.Update` выполняет изменение копии комнаты под блокировкой и сохраняет его только при отсутствии ошибки, чтобы параллельные сообщения и действия плеера не терялись.

## Запуск

### Docker (рекомендуется)

Нужен только Docker с Compose. Единственный файл конфигурации — `docker-compose.yaml` в корне проекта:

```sh
docker compose up --build -d
```

Откройте http://localhost:8081. Порт можно переопределить: `WATCHROOM_PORT=9000 docker compose up --build -d`. Остановка: `docker compose down`. Обновление базовых образов и пересборка: `docker compose build --pull && docker compose up -d`.

Используются официальные образы `golang:1.27-alpine`, `node:26-alpine`, `nginx:alpine`, `alpine:latest`. Теги без фиксации патч-версии получают новые обновления при пересборке с `--pull`.

### Без Docker

Нужны Go 1.27+, Node.js 20.19+ (или 22.12+), npm.

В одном терминале:

```sh
cd backend
go run ./cmd/server
```

В другом:

```sh
cd frontend
npm install
npm run dev
```

Откройте адрес, указанный Vite (обычно http://localhost:5173). Создайте комнату с **прямой HTTP(S)-ссылкой на видеофайл** (например MP4), скопируйте приглашение в шапке и откройте его в другом браузере. Видео должно воспроизводиться самим браузером каждого участника; ссылки на страницы YouTube/Кинопоиска, локальные файлы и DRM-потоки не поддерживаются. Браузер может потребовать нажатие на плеер перед первым автоматическим воспроизведением.

Сейчас данные хранятся **в памяти одного процесса**: после перезапуска комнаты исчезнут. PostgreSQL-миграции в `backend/migrations` относятся к незавершённому прототипу и в этом MVP не используются. Регистрация, загрузка файлов и удаление неактивных участников пока не реализованы; количество зрителей отражает число входов, а не число активных вкладок. Код комнаты — приглашение: не используйте его для приватных материалов.

## Проверка

```sh
cd backend
make test
make vet
```

Проверяются репозиторий (копии, откат неуспешных изменений, подписки), сервис (доступ, входные данные, история и конкурентные сообщения), HTTP и SSE. Команды используют `./cmd/... ./internal/...`, чтобы не читать закрытые файлы старой PostgreSQL в `backend/out`.

Сборка frontend: `cd frontend && npm run build`.

Из `backend` также доступны `make env-up`, `make env-down` и `make logs`: они используют корневой Compose и не требуют `.env`. Старые команды PostgreSQL и миграций заменены, поскольку действующий MVP базу не использует.
